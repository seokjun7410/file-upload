# 스프린트 1 파일 저장·업로드 오류 정책 결정

## 결정이 필요한 이유

파일 업로드는 정책 판정만으로 끝나지 않고 파일 저장 위치, 서버 생성 파일명, 잘못된 파일 입력과 저장 장애의 오류 의미를 함께 정의해야 한다. 이 규칙이 불명확하면 API 응답과 실제 저장 결과가 달라지고, 원본 파일명이 저장 경로에 노출될 수 있다.

## 선택지와 사용자 결정

### 저장 위치

- 프로젝트 고정 `./uploads`: 구현과 운영 확인이 단순하고 스프린트의 로컬 저장 요구에 맞는다.
- 설정 가능한 경로: 환경 분리는 쉽지만 이번 범위에 설정 계약이 추가된다.
- 시스템 임시 경로: 테스트 격리는 쉽지만 영속 저장 요구와 맞지 않는다.

**결정: 프로젝트 고정 `./uploads`.**

### 파일명

- UUID 기반 서버 파일명을 저장하고 실제 생성 파일명을 응답한다: 충돌과 경로 조작을 피하고 응답 의미가 저장 결과와 같다.
- UUID로 저장하되 원본명을 응답한다: 사용자 경험은 좋지만 응답과 물리 파일의 의미가 분리된다.
- 원본명을 저장한다: 구현은 단순하지만 충돌·경로 조작 위험이 커진다.

**결정: UUID와 정규화된 마지막 확장자로 파일명을 만들고, 생성된 파일명을 응답한다.**

### 잘못된 파일 입력과 저장 장애

- 누락·빈 파일·무확장 파일은 `400 INVALID_FILE`로 거부한다.
- 차단 확장자는 `422 BLOCKED_EXTENSION`으로 거부한다.
- 서버 저장 장애는 `500 FILE_UPLOAD_FAILED`로 반환하며 내부 경로와 예외를 노출하지 않는다.

## 영향

- 서버는 원본 파일명을 저장 경로에 사용하지 않는다.
- 화면은 확장자 차단을 중복 판단하지 않고 서버 응답을 표시한다.
- 오류 코드별 처리가 가능하므로 사용자 입력 오류와 서버 저장 장애를 구분할 수 있다.
