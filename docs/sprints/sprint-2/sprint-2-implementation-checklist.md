# 스프린트 2 구현 순서·결정 게이트 체크리스트

> 상태: `feat/upload-policy-reliability@a840db2` 기준 ADR 0005·0006·0009·0011·0012·0013·0014·0015 구현 완료·브라우저 smoke 주요 시나리오 통과·VoiceOver/실제 200% 확대·409 화면 분기 확인 대기
>
> 기준 문서: [스프린트 2 PRD](sprint-2-prd.md), [ADR 구현 상태 점검](../../adr/adr-implementation-status-review-2026-08-30.md)

> 구현 상태는 문서 브랜치의 파일이 아니라 위 기준 브랜치의 코드·설정·테스트로 판정한다. 이 브랜치에 병합된 커밋만 완료로 표시한다.

## 사용 규칙

- 체크리스트는 위에서 아래 순서로 진행한다. 선행 작업이 끝나지 않은 작업은 시작하지 않는다.
- 각 작업의 `시작 전 질문`이 남아 있으면 코드·설정·API를 변경하지 않는다. 질문 문서에 배경·선택지·영향·예시를 기록하고 사용자 답변을 받은 뒤 해당 항목을 시작한다.
- 질문의 답변이 기존 ADR을 변경하면 먼저 ADR과 API 계약을 문서 브랜치에서 갱신한다. `proposed` ADR은 채택·변경·철회 중 하나로 확정되기 전에는 구현하지 않는다.
- 모든 구현 작업은 한글 `@DisplayName`의 Red 테스트부터 시작해 최소 Green 구현, 리팩터링, 관련 테스트, 전체 `./gradlew test` 순서로 확인한다.
- 기능 코드와 문서를 같은 직접 커밋에 섞지 않는다. 문서는 `docs` 브랜치에서, 기능 코드는 문서 병합 뒤 `feat/<작업명>` 브랜치에서 진행한다.

## 2. ADR 0009 — multipart 용량 제한과 413 계약

- [x] 파일 10MB, 요청 전체 12MB 제한의 설정 테스트와 413 오류 매핑 테스트를 작성한다.
- [x] multipart 용량 초과 예외가 넓은 파일 입력 오류 처리보다 먼저 413으로 변환되도록 구현한다.
- [x] 프런트가 용량 초과 오류를 안전하게 표시하는지 확인한다.

시작 전 질문:

- 용량 초과의 안정적인 오류 코드는 `FILE_SIZE_EXCEEDED`로 확정한다.
- 업로드 오류의 장기 응답 형식은 ADR 0013 작업 전까지 기존 `code`·`message`를 유지하고, `requestId`·`context` 형식은 ADR 0013에서 별도로 도입한다.

중단 규칙: 위 오류 코드와 응답 형식이 확정되기 전에는 413 handler와 API 계약을 구현하지 않는다. 두 항목은 10MB·12MB 구현에서 확정했다.

완료 기준: 경계 초과 요청은 확장자·MIME·파일 저장 전에 413과 확정된 오류 계약으로 거부된다. 구현 완료(commit `c96eab7`).

## 4. ADR 0005 — 실행 MIME denylist 결정 문서

- [x] 지원 후보 형식·MIME·위장 파일 위험을 조사해 질문 문서를 작성한다.
- [x] 사용자 답변을 API 계약과 ADR 보완 문서에 반영한다.
- [x] 실행 MIME denylist, 미확인 MIME 경고·허용, `.txt`·`text/plain` 허용 규칙을 이후 검증 기준으로 확정한다.

시작 전 질문:

- 실행 가능한 바이너리 MIME만 차단하고, `text/plain`과 미확인 MIME는 허용한다.
- `application/octet-stream` 등 `UNKNOWN` MIME은 경고 후 업로드를 계속하고, `IOException`으로 분석 자체가 실패한 `FAILED` 결과는 `FILE_TYPE_DETECTION_FAILED`로 거부한다.
- 실행 MIME 차단 오류 코드는 `BLOCKED_EXECUTABLE_MIME`으로 확정한다.

중단 규칙: 실행 MIME 카탈로그와 미확인 MIME 처리 의미가 확정되기 전에는 Tika 의존성이나 차단 로직을 추가하지 않는다. 위 항목은 ADR 0005와 API 계약에 반영했다.

완료 기준: 질문 문서의 답변이 API 계약과 ADR에 반영되고, 다음 구현 작업에서 사용할 실행 MIME denylist가 확정된다.

## 5. ADR 0005 — 콘텐츠 기반 MIME 검증 구현

- [x] 실행 MIME 차단, `.txt` 허용, `UNKNOWN` MIME 경고·허용, `FAILED` MIME 감지 실패 거부의 Red 테스트를 작성한다.
- [x] Tika 콘텐츠 감지와 애플리케이션 소유 실행 MIME denylist를 분리한 검증 모듈을 구현한다.
- [x] MIME 검증이 확장자 정책 판정과 파일 저장보다 먼저 실패하고, 내부 감지 정보가 외부 오류에 노출되지 않는지 확인한다.

시작 전 질문: 작업 4의 실행 MIME 카탈로그, 미확인 MIME 처리, 오류 코드가 문서로 확정되었는지 확인한다. 확정된 문서는 ADR 0005와 스프린트 1 API 계약이다.

완료 기준: 실행 MIME 파일은 `BLOCKED_EXECUTABLE_MIME`으로 저장 전에 거부되고, `.txt`·`text/plain`과 `UNKNOWN` MIME은 기존 확장자 정책을 통과하면 저장된다. `FAILED` MIME 감지는 `FILE_TYPE_DETECTION_FAILED`로 저장 전에 거부된다.

## 6. ADR 0013 — 업로드 오류 requestId·context·FE 메시지

- [x] 업로드 오류에 requestId와 최소 context가 포함되고, 내부 경로·원본 파일명·stack trace가 노출되지 않는 controller 테스트를 작성한다.
- [x] requestId 생성·로그 상관관계·오류 응답 조립을 공통 경계로 구현한다.
- [x] FE가 서버 `message`가 아닌 오류 코드와 context로 업로드 안내를 표시하도록 구현한다. (commit `a89a5ef`)
- [x] 정상 `.txt` 업로드와 차단 `env` 업로드에서 FE 안내 문구를 확인한다.
- [x] MIME 거부와 413 용량 초과 안내를 브라우저에서 확인한다.
- [ ] 처리 중 `409` 재시도 안내의 실제 화면 분기를 브라우저에서 확인한다. API의 `409 + Retry-After`와 FE 재시도 상수·문구는 확인했지만, IAB에서 동일 requestId 응답을 화면에 주입하는 경로는 미확정이다.
- [x] 정책 오류 code 기반 한국어 안내와 오류·삭제 후 포커스 복귀를 수정하고 브라우저에서 재검증한다. (commit `a840db2`)

시작 전 질문: 없음. `Idempotency-Key`의 UUID v4를 requestId로 사용하고, 기존 `message`는 호환 기간 동안 유지하며, context에는 안전한 최소 값만 담는 것으로 확정했다.

중단 규칙: 외부 오류에 노출할 context와 `message` 호환 기간이 정해지기 전에는 응답 DTO·FE 분기 계약을 변경하지 않는다. 구현 완료(commit `164a8e0`).

완료 기준: 사용자 메시지 책임은 FE에 있고, 운영자는 requestId·오류 코드·상태로 한 요청의 오류를 추적할 수 있다.

완료 기준: 최종 경로에는 완료 파일만 존재하고, DB 상태로 미완료 업로드를 식별·복구·정리할 수 있다. 구현 완료(commit `164a8e0`).

- [x] requestId 보존기간·만료와 멱등키 기록 정리는 현재 파일 업로드 범위에 도입하지 않는다. 파일 생명주기·물리 파일 삭제 정책이 별도로 확정되기 전에는 만료 후 재사용 동작을 추가하지 않는다.

시작 전 질문: 없음. `409 + Retry-After`, 지문 미사용, capped backoff 1~30초, FE 자동 재시도 최대 3회·전체 30초, 결과 조회 API 제외로 확정했다.

중단 규칙: 처리 중 HTTP 계약·요청 지문·보존 기간이 확정되기 전에는 멱등성 테이블과 FE 재시도를 구현하지 않는다.

완료 기준: 응답 유실 뒤 같은 논리적 업로드를 재시도해도 중복 파일이 생기지 않고, FE 재시도 포기는 서버 저장 상태를 임의로 실패 처리하지 않는다. 구현 완료(commit `164a8e0`).
