# 스프린트 1: 파일 업로드 확장자 차단 정책

## 바로 다음 작업

파일 업로드 시 확장자 기반 차단 정책을 관리하고, 실제 파일 업로드 요청에 동일한 정책을 강제하는 수직 슬라이스를 구현한다.

현재 프로젝트는 Spring Boot 3.5, Spring Data JPA, H2 파일 DB, Thymeleaf를 사용한다. 확장자 정책의 도메인·JPA·초기화·정책 REST API와 최소 Thymeleaf 페이지는 구현되어 있으며 파일 저장·Axios 화면은 후속 단계다.

구현 시 준수할 API 계약은 [스프린트 1 API 문서](sprint-1-file-upload-api.md), 구현 완료 판정은 [스프린트 1 FE/BE 구현 완료 체크리스트](sprint-1-file-upload-checklist.md), 단일 커밋 작업 순서는 [스프린트 1 단일 커밋 작업 순서](sprint-1-file-upload-single-commit-sequence.md)를 기준으로 한다.

## 왜 하는가

확장자 차단 정책을 화면과 DB에만 저장하면 정책은 존재하지만 실제 파일 업로드를 막을 수 없다. 따라서 이번 스프린트에서는 다음 두 계층을 함께 완성해야 한다.

1. **정책 관리 계층**: 고정·커스텀 차단 확장자를 조회하고 저장·삭제한다.
2. **업로드 처리 계층**: 업로드 파일의 확장자를 정책과 비교해 차단 또는 저장한다.

정책 변경 결과는 새로고침 후에도 유지되어야 하며, 업로드 요청은 화면 우회 여부와 관계없이 서버에서 최종 검증한다.

## 기대 결과

사용자는 정책 관리 화면에서 고정 확장자를 체크하거나 커스텀 확장자를 추가·삭제할 수 있다. 이후 파일 업로드를 시도하면 서버가 저장된 정책을 조회하여 결과를 결정한다.

```text
정책 변경 → DB 저장
        ↓
파일 업로드 요청 → 서버가 파일 확장자 추출
                 → 차단 정책 조회
                 → 차단이면 명확한 사유 반환
                 → 허용이면 파일 저장 및 성공 응답
```

### 고정 확장자

- 대상: `bat`, `cmd`, `com`, `cpl`, `exe`, `scr`, `js`
- 최초 상태: 모두 `unCheck`
- 체크/체크 해제 결과: DB에 저장
- 새로고침 결과: DB에 저장된 상태를 그대로 표시
- 커스텀 확장자 목록에는 고정 확장자를 표시하지 않음

### 커스텀 확장자

- 입력 최대 길이: 20자
- `추가` 클릭 시 검증 후 DB 저장 및 목록 반영
- 최대 등록 수: 200개
- 항목별 `X` 클릭 시 DB에서 삭제
- 동일 확장자는 중복 저장하지 않음
- 권장 정규화: 앞뒤 공백 제거 및 소문자 변환 후 중복·정책 비교
- 입력값의 점(`.`) 포함 여부와 허용 문자 범위는 구현 시 하나의 규칙으로 통일한다. 권장 입력 형식은 점을 제외한 확장자명이다. 예: `sh`

### 실제 파일 업로드

- 업로드 대상 확장자가 고정 또는 커스텀 차단 정책에 포함되면 저장하지 않는다.
- 거부 응답에는 최소한 “차단된 확장자”와 “업로드가 거부되었다”는 사유를 포함한다.
- 차단 대상이 아닌 파일은 정해진 저장 위치에 저장하고 성공 결과를 반환한다.
- 파일명에 확장자가 없거나 확장자 추출이 불가능한 경우의 처리 규칙은 구현 시 명시한다. 권장 정책은 확장자 없는 파일을 허용하되, 저장 파일명은 서버가 생성하는 방식이다.

## 권장 구현 순서

1. **도메인 및 저장 모델**
   - `ExtensionPolicy` 단일 엔티티에 `extension`, `policyType`, `blocked`를 저장한다.
   - `policyType`으로 고정 정책과 커스텀 정책을 구분한다.
   - 고정 카탈로그와 커스텀 정책이 서로의 유형으로 등록되지 않도록 도메인에서 검증한다.
   - 확장자 유일성, 필수값, 정책 유형과 상태 조합은 DB 제약으로 보장한다.
   - 애플리케이션 최초 실행 시 고정 확장자 7개를 `unCheck`로 초기화한다.

2. **정책 서비스**
   - 고정 확장자 체크/해제
   - 커스텀 확장자 추가/삭제
   - 최대 200개, 길이 20자, 중복 입력 검증
   - 업로드 확장자가 차단 대상인지 판정하는 단일 정책 조회 기능

3. **정책 관리 화면 및 엔드포인트**
   - 고정 확장자 체크박스 목록을 표시한다.
   - 커스텀 확장자 입력·추가·삭제 UI를 제공한다.
   - 성공·중복·길이 초과·최대 개수 초과 메시지를 표시한다.
   - 새로고침 시 DB 상태를 다시 조회해 렌더링한다.

4. **파일 업로드 처리**
   - `multipart/form-data` 업로드 엔드포인트를 추가한다.
   - 서버에서 파일 확장자를 추출하고 정책 서비스에 판정을 위임한다.
   - 차단 시 파일 저장을 수행하지 않고 명확한 오류를 반환한다.
   - 허용 시 서버 생성 파일명으로 저장하고 성공 결과를 반환한다.

5. **통합 검증**
   - 정책 관리 화면과 실제 업로드 화면에서 동일한 DB 정책이 적용되는지 확인한다.
   - 기존 예제 화면 및 테스트에 영향을 주지 않는지 확인한다.

## 최소 API/화면 계약

구체적인 URL은 기존 프로젝트의 컨트롤러 구조에 맞춰 정하되, 다음 동작을 제공해야 한다.

| 기능 | 입력 | 성공 결과 | 실패 결과 |
|---|---|---|---|
| 정책 화면 조회 | 없음 | 고정 확장자 상태와 커스텀 목록 표시 | 서버 오류 |
| 고정 확장자 상태 변경 | 확장자, 체크 상태 | DB 저장 후 최신 상태 표시 | 존재하지 않는 고정 확장자 오류 |
| 커스텀 추가 | 확장자 문자열 | DB 저장 후 목록에 표시 | 빈 값, 20자 초과, 중복, 200개 초과 |
| 커스텀 삭제 | 커스텀 항목 식별자 또는 확장자 | DB 삭제 후 목록에서 제거 | 존재하지 않는 항목 오류 |
| 파일 업로드 | multipart 파일 1개 | 허용 시 저장 성공 | 차단 확장자와 거부 사유 반환 |

## 테스트

다음 순서로 행동 중심 테스트를 작성한다.

1. 고정 확장자 7개가 최초에 모두 `unCheck` 상태로 노출된다.
2. 고정 확장자를 체크하면 DB에 저장되고 조회 시 체크 상태가 유지된다.
3. 고정 확장자를 해제하면 DB 상태도 `unCheck`로 변경된다.
4. 고정 확장자가 커스텀 목록에 나타나지 않는다.
5. 유효한 커스텀 확장자를 추가하면 DB와 목록에 반영된다.
6. 커스텀 확장자 입력이 20자를 초과하면 저장되지 않는다.
7. 동일 확장자를 다시 추가하면 중복 저장되지 않고 안내 메시지가 반환된다.
8. 커스텀 확장자가 200개를 초과하면 201번째 항목은 저장되지 않는다.
9. 커스텀 항목을 삭제하면 DB와 화면 목록에서 제거된다.
10. 차단된 고정 확장자 파일 업로드는 거부되고 파일이 저장되지 않는다.
11. 차단된 커스텀 확장자 파일 업로드는 거부되고 파일이 저장되지 않는다.
12. 허용된 파일 업로드는 성공하고 파일이 저장된다.
13. 정책 변경 후 별도 업로드 요청에서 변경된 정책이 즉시 적용된다.
14. 대소문자 또는 앞뒤 공백이 있는 커스텀 확장자 입력이 정규화 규칙에 따라 중복·차단 판정된다.

도메인 단위 테스트로 검증 가능한 정책 규칙을 먼저 작성하고, 이후 JPA 저장소 테스트와 MockMvc 또는 통합 테스트로 DB 유지·화면·실제 multipart 업로드 흐름을 검증한다.

## 완료 조건

- 고정 확장자 7개의 체크/해제 상태가 DB에 저장되고 새로고침 후 유지된다.
- 커스텀 확장자가 최대 200개까지 등록·조회·삭제된다.
- 20자 초과 및 중복 입력이 저장되지 않는다.
- 고정 확장자가 커스텀 목록에 노출되지 않는다.
- 고정 또는 커스텀 차단 확장자 파일은 실제 업로드에서 서버가 거부한다.
- 거부된 파일은 저장되지 않으며, 응답 또는 화면에 차단 확장자와 사유가 표시된다.
- 허용된 파일은 성공적으로 저장된다.
- 위 테스트가 통과한다.

## 이번 작업에서 하지 않을 것

- 확장자 외 MIME 타입·파일 내용·악성코드 검사
- 사용자별 또는 조직별 정책 분리
- 관리자 권한·인증/인가
- 파일 목록 조회, 다운로드, 미리보기, 업로드 이력 관리
- 대용량 파일 업로드 최적화 및 외부 오브젝트 스토리지 연동
- 운영 환경용 바이러스 검사나 보안 감사 기능
- 고정 확장자 목록을 사용자가 추가·편집하는 기능
