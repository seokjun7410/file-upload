# 스프린트 1 FE/BE 구현 완료 체크리스트

> 상태: 1~4단계 정책 REST API 구현 완료, 파일 저장·Axios 화면 미완료
>
> 기준 문서: [스프린트 1 확장자 차단 정책](sprint-1-file-upload-extension-policy.md), [스프린트 1 API 계약](sprint-1-file-upload-api.md)

현재 완료 범위는 `ExtensionPolicy` 단일 엔티티, fixed/custom 카탈로그 불변식, DB 제약, quota 기반 커스텀 최대 200개 등록, 고정 정책 초기화, 예제 기능 제거, 서버 `Model` 없는 최소 Thymeleaf 페이지, 정책 REST API와 공통 오류 응답이다. multipart 파일 저장·Axios 화면과 업로드 통합·수동 검증은 아직 완료되지 않았다.

## 1. 완료 판정 원칙

- [ ] API 계약 문서의 URL, HTTP 메서드, 요청 형식, 응답 형식, 상태 코드를 변경 없이 구현한다.
- [ ] 체크박스 항목은 코드와 자동화 테스트 또는 실제 화면 확인으로 근거를 남긴다.
- [ ] FE와 BE가 서로 다른 정규화·오류 해석·상태 표시 규칙을 사용하지 않는다.
- [ ] 아래 필수 항목을 모두 충족하고 `./gradlew test`와 `git diff --check`가 성공해야 스프린트 완료로 판정한다.

## 2. API 계약 기준

| 기능 | 완료 확인 기준 |
|---|---|
| 정책 조회 | `GET /api/v1/extension-policies`, `200 OK`, `fixed` 7개와 `custom` 목록 반환 |
| 고정 확장자 변경 | `PATCH /api/v1/extension-policies/fixed/{extension}`, `blocked` JSON 요청·응답, 알 수 없는 확장자는 `404` |
| 커스텀 확장자 추가 | `POST /api/v1/extension-policies/custom`, `201 Created`, 실패 시 `400` 또는 `409` |
| 커스텀 확장자 삭제 | `DELETE /api/v1/extension-policies/custom/{extension}`, 성공 시 `204 No Content`, 없는 항목은 `404` |
| 파일 업로드 | `POST /api/v1/files`, `multipart/form-data`의 `file` 필드, 성공 시 `201`, 차단 시 `422` |
| 공통 오류 | `{ "code": "ERROR_CODE", "message": "..." }` 형식으로 반환 |

- [x] 정책 API가 `/api/v1/extension-policies` Base URL 아래에 구현되어 있다.
- [ ] 파일 업로드 API가 `/api/v1/files` Base URL 아래에 구현되어 있다.
- [x] 정책 API 성공 응답과 오류 응답의 본문·상태 코드가 API 문서와 일치한다.
- [x] 확장자 입력은 앞뒤 공백 제거 후 소문자로 정규화하고 점(`.`)을 제외한 형식으로 처리한다.
- [ ] 파일 업로드가 없는 파일, 업로드할 수 없는 요청, 차단 확장자를 계약된 상태 코드로 구분한다.

## 3. FE 완료 기준: Thymeleaf + Axios

- [x] Thymeleaf는 화면 구조와 정적 초기 페이지를 제공하며 `Model` 데이터를 사용하지 않는다.
- [ ] 정책 목록·체크 상태·커스텀 목록은 페이지 렌더링 시 Axios `GET /extension-policies` 결과로 구성한다.
- [ ] 고정 확장자 체크/해제는 Axios `PATCH`로 서버에 저장한 뒤 응답 상태를 화면에 반영한다.
- [ ] 커스텀 확장자 추가는 Axios `POST`, 삭제는 Axios `DELETE`로 호출한다.
- [ ] 파일 선택·업로드는 `FormData`의 `file` 필드로 Axios `POST /files`를 호출한다.
- [ ] Axios 요청 경로가 API 계약의 Base URL과 일치한다.
- [ ] 성공 응답은 최신 정책 목록, 추가 결과, 삭제 완료, 업로드 완료를 사용자에게 표시한다.
- [ ] `400`, `404`, `409`, `422` 및 공통 오류 JSON의 `message`를 사용자 메시지로 표시한다.
- [ ] 정책 화면 새로고침 시 서버의 최신 DB 상태를 다시 조회한다.
- [ ] 차단 업로드 실패 시 차단 확장자와 업로드 거부 사유를 표시한다.
- [ ] 허용 업로드 성공 시 API가 반환한 파일명과 완료 메시지를 표시한다.
- [ ] 화면 검증만으로 업로드 허용 여부를 결정하지 않는다.

## 4. BE 완료 기준: REST API

- [x] 정책 API 요청 처리는 `@RestController`로 구현하고 Thymeleaf view를 반환하지 않는다.
- [x] 정책 API 메서드에서 `Model`, redirect, 서버 렌더링용 화면 상태를 사용하지 않는다.
- [x] 정책 API 요청·응답은 API 계약에 맞는 DTO 또는 record로 표현한다.
- [x] `GET /extension-policies`는 DB의 최신 상태를 반환한다.
- [x] 애플리케이션 최초 실행 시 고정 확장자 7개가 모두 `blocked: false`로 준비된다.
- [x] 고정 확장자 변경 결과가 DB에 저장되고 다음 조회에도 유지된다.
- [x] 커스텀 확장자는 정규화 후 저장하며 빈 값·20자 초과·중복·200개 초과를 거부한다.
- [x] 커스텀 목록에 고정 확장자를 저장하거나 반환하지 않는다.
- [x] 커스텀 삭제 성공 시 본문 없는 `204 No Content`를 반환한다.
- [ ] 업로드 확장자는 서버에서 추출하고 저장된 정책으로 차단 여부를 다시 판정한다.
- [ ] 차단 파일은 파일 저장 로직을 실행하지 않고 `422`와 `BLOCKED_EXTENSION`을 반환한다.
- [ ] 허용 파일은 정해진 저장 위치에 서버 생성 파일명으로 저장하고 `201` 응답을 반환한다.
- [x] 정책 API 공통 오류 응답의 `code`와 `message`가 계약에 맞게 일관된다.
- [x] 기존 `ExampleEntity`, `ExampleRepository`, `ExamplePageController`와 예제 저장 화면·엔드포인트·관련 테스트를 제거한다.

## 5. 통합 동작 기준

- [ ] 고정 확장자를 차단으로 변경한 직후 해당 확장자 파일 업로드가 거부된다.
- [ ] 고정 확장자를 차단 해제한 뒤 해당 확장자 파일 업로드가 허용된다.
- [ ] 커스텀 확장자를 추가한 직후 해당 확장자 파일 업로드가 거부된다.
- [ ] 커스텀 확장자를 삭제한 뒤 해당 확장자 파일 업로드가 허용된다.
- [ ] 대소문자와 앞뒤 공백이 있는 입력도 동일한 정규화 규칙으로 중복·차단 판정된다.
- [ ] 차단된 파일은 업로드 전후 저장 위치에 새 파일이 생성되지 않는다.
- [ ] 허용된 파일은 저장되고 성공 응답이 화면에 반영된다.
- [ ] 기존 예제 제거 후 루트 페이지와 신규 파일 업로드 페이지가 정상적으로 열리고 애플리케이션이 기동된다.

## 6. 자동화 테스트 기준

- [x] 도메인 테스트로 고정 확장자 초기 상태, 정규화, 길이, 중복, 최대 개수 규칙을 검증한다.
- [x] JPA 테스트로 정책 추가·조회, DB 제약, 초기화 후 상태 유지를 검증한다.
- [x] REST MockMvc 테스트로 정책 API의 요청 형식, 성공 상태 코드, 응답 JSON, 오류 형식을 검증한다.
- [ ] multipart 업로드 테스트로 고정·커스텀 차단, 허용 저장, 차단 파일 미저장을 검증한다.
- [ ] 정책 변경 후 별도 업로드 요청에 변경된 정책이 적용되는지 검증한다.
- [x] Thymeleaf 페이지 테스트로 화면이 정상 렌더링되고 서버 `Model` 데이터에 의존하지 않는지 검증한다.
- [x] 전체 테스트 실행 결과가 성공한다: `./gradlew test`
- [x] 변경 문서와 코드의 공백 오류 검사가 성공한다: `git diff --check`

## 7. 수동 확인 기준

- [ ] 브라우저에서 정책 페이지를 열었을 때 Axios 정책 조회 요청이 성공한다.
- [ ] 고정 확장자 체크·해제 후 새로고침해도 선택 상태가 유지된다.
- [ ] 커스텀 확장자 추가·삭제 결과가 화면 목록과 DB에 동일하게 반영된다.
- [ ] 차단 파일 업로드 시 파일이 저장되지 않고 차단 사유가 표시된다.
- [ ] 허용 파일 업로드 시 파일이 저장되고 성공 메시지가 표시된다.
- [ ] 브라우저 개발자 도구에서 API 요청의 URL, 메서드, 요청 본문, 응답 상태 코드가 계약과 일치한다.
