# 고정 확장자 정책은 서버 저장 상태를 단일 기준으로 사용

## 배경

고정 확장자 정책 변경 요청이 실패하면 서버가 변경을 적용하지 않은 것인지, 변경은 적용했지만 응답만 전달되지 않은 것인지 클라이언트가 확정할 수 없다. 이때 사용자가 시도한 값을 그대로 신뢰하면 화면과 저장된 정책이 서로 달라질 수 있다.

## 결정

- 고정 확장자 차단 상태의 단일 기준은 서버에 저장된 정책이다.
- 정책 변경 결과를 확정할 수 없으면 전체 정책 상태를 다시 조회해 클라이언트 상태를 서버와 일치시킨다.
- 정책 재조회도 실패하면 현재 상태를 미확정으로 취급하고, 저장 성공 또는 실패를 단정하지 않는다.
- 변경 실패 뒤 상태 재확인이 끝나기 전에는 후속 정책 변경을 허용하지 않는다.

## 결과

- 응답 유실이 발생해도 이후 조회 결과를 기준으로 정책 상태의 일관성을 회복할 수 있다.
- 실패 복구를 위해 추가 조회가 발생한다.
- 변경과 재조회가 모두 실패한 동안에는 최신 상태를 보장할 수 없으므로 미확정 상태를 사용자에게 알려야 한다.
