# 알려진 비실행 파일 형식만 허용하는 업로드 검증 정책

파일 확장자는 변경할 수 있고 HTTP `Content-Type`은 클라이언트가 전달하는 값이므로 단독으로 신뢰할 수 없다. 콘텐츠 기반 MIME 감지를 사용하더라도 파일의 실행 가능성이나 악성 여부까지 완전히 판단할 수는 없다.

## 결정

- Apache Tika `tika-core`를 파일 콘텐츠 기반 MIME 감지 용도로 사용한다.
- Tika는 Java 애플리케이션에 직접 통합할 수 있고, 감지 기능만 사용할 때 Parser 의존성을 추가하지 않아도 되므로 선택한다.
- 확장자와 MIME은 단순 문자열 동일성이 아니라, 지원 형식별 호환 관계로 검증한다.
- 현재는 지원이 명확한 비실행 파일 형식만 허용한다.
- 실행파일·스크립트·매크로 포함 가능 형식·MIME 감지 불가 형식·확장자와 MIME이 호환되지 않는 형식은 허용하지 않는다.
- Tika는 MIME 감지만 담당하고, 허용 형식과 최종 업로드 여부는 애플리케이션이 결정한다.
- 문서 Parser, 악성코드·바이러스 검사는 이 결정의 범위에 포함하지 않는다.

## 고려한 대안

### MIME 불일치를 허용

기존 확장자 차단정책과 호환되지만, 확장자를 바꾼 실행파일이 통과할 수 있다. 안전한 파일만 허용한다는 정책을 설명하기 어렵다.

### 확장자와 MIME이 호환될 때만 허용

위장 파일을 줄일 수 있지만, 사실상 지원 형식 허용리스트가 된다. 감지 불가 형식과 지원하지 않는 형식은 거부해야 하며, 컨테이너·평문 형식에 따른 오탐 가능성을 감수해야 한다.

### Parser와 악성코드 검사까지 도입

더 높은 검증 수준을 기대할 수 있지만 Parser 격리, 타임아웃, 리소스 제한과 별도 악성코드 검사 인프라가 필요하다. 현재 결정에서는 후속 범위로 둔다.

## 결과

- MIME 감지만으로 안전성을 보장하지 않는다는 한계를 명확히 한다.
- 허용 범위가 명확한 비실행 파일 형식으로 제한된다.
- 새로운 파일 형식을 허용하려면 MIME 매핑과 비실행 여부를 먼저 검토해야 한다.
- 실행파일 식별, 악성코드 검사, 격리 저장 및 비동기 검증 체계가 마련되면 허용 범위를 재검토한다.
