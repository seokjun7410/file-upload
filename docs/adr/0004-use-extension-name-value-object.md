# 확장자 이름을 값 객체로 관리

확장자 입력은 공백 제거와 소문자 변환이라는 정규화와 빈 값·길이·점 포함 여부라는 형식 검증을 함께 거쳐야 한다. 이 흐름이 엔티티·정책 서비스·파일 업로드 서비스에 각각 노출되면 호출자가 처리 순서를 기억해야 하고, 정규화되지 않은 문자열이 도메인 내부로 전달될 수 있다.

## 결정

- 정규화되고 형식 검증된 확장자 이름을 `ExtensionName` 값 객체로 표현한다.
- `ExtensionName` 생성 시 `ExtensionNormalizer`로 표기를 정규화하고 `ExtensionValidator`로 형식을 검증한다.
- 엔티티와 서비스는 원본 문자열을 직접 정규화·검증하지 않고 `ExtensionName`에서 유효한 값을 얻는다.
- JPA 컬럼은 기존 `String`으로 유지하고, 데이터베이스 매핑 범위는 확장하지 않는다.
- 파일명에서 확장자를 찾는 책임은 파일 업로드 기능에 남기되, 추출된 문자열의 정규화·검증은 `ExtensionName`에 위임한다.
- API 입력 오류와 파일 입력 오류처럼 사용처별로 다른 예외 변환은 각 기능의 Adapter가 담당한다.

## 결과와 주의점

- 정규화·검증 순서와 유효한 확장자 값의 생성 규칙이 `ExtensionName`에 집중된다.
- `ExtensionNormalizer`는 표기 변환만, `ExtensionValidator`는 형식·정책 불변식 검증만 담당한다.
- 값 객체 생성 단계에서 예외가 발생하므로 API와 파일 업로드 기능은 각자의 오류 의미로 변환해야 한다.
- JPA 엔티티가 `String`을 저장하므로 현재 스키마와 저장소 계약은 변경되지 않는다.
