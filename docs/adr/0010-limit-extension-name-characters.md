# 커스텀 확장자 이름의 허용 문자를 제한한다

## 문맥

[ADR 0004](0004-use-extension-name-value-object.md)는 확장자 이름의 정규화와
기본 형식 검증을 `ExtensionName` 값 객체에 집중하도록 결정했다. 그러나
확장자 이름에 어떤 문자를 허용할지는 별도 정책으로 확정하지 않았다.

허용 문자를 제한하지 않으면 공백, 점, 구분자 또는 기타 특수문자가 정책 값에
들어갈 수 있다. 그러면 확장자 비교와 파일명 추출 결과가 달라질 수 있고,
사용자가 입력한 정책의 의미도 일관되지 않게 해석될 수 있다.

## 결정

- 앞뒤 공백을 제거한 뒤의 커스텀 확장자는 한글·영문·숫자로만 구성할 수 있다.
- 정규화 후 남은 공백·점(`.`)·경로 구분자·기타 특수문자는 허용하지 않는다.
- 앞뒤 공백 제거와 소문자 변환은 [ADR 0004](0004-use-extension-name-value-object.md)의 정규화 규칙을 따른다.
- 허용 문자 검증은 커스텀 정책 등록과 파일 업로드 확장자 처리에서 동일한
  `ExtensionName` 생성 경계를 통해 수행한다.
- 고정 확장자는 코드 카탈로그에 정의된 값만 사용하므로 이 허용 문자 정책을
  별도로 입력받지 않는다.

## 예시

```text
허용: hwp, mp3, 7z, 한글, ` mp3 ` → `mp3`
거부: tar.gz, my-file, file!, space name
```

## 고려한 대안

### 점만 제외하고 나머지 문자를 허용

구현은 단순하지만 공백·경로 구분자·특수문자가 정책 값에 들어갈 수 있다.
정책 조회와 파일명에서 추출한 값의 비교 기준이 불명확해지므로 선택하지 않는다.

### 영문·숫자만 허용

파일 확장자의 관례에는 잘 맞지만 한글 확장자를 입력하려는 사용자의 요구를
제한한다. 현재 제품의 입력 정책에서는 한글도 허용하므로 선택하지 않는다.

### 한글·영문·숫자·일부 구분 기호 허용

`tar.gz`와 같은 복합 확장자를 표현할 수 있지만, 현재 업로드 차단은 최종
확장자만 판단한다는 [ADR 0007](0007-use-final-file-extension-for-upload-blocking.md)의
정책과 충돌한다. 복합 확장자 정책이 필요해지면 별도 ADR에서 결정한다.

## 결과와 한계

- 정책 값과 업로드에서 추출한 확장자의 형식이 일관된다.
- 숫자가 포함된 `mp3`, `7z`와 한글 확장자를 허용할 수 있다.
- 운영체제나 파일 형식이 허용하는 모든 확장자 표현을 지원하는 것은 아니다.
- 허용 문자 외의 입력은 `INVALID_EXTENSION` 오류로 처리한다.

## 기존 결정과의 관계

이 ADR은 [ADR 0004](0004-use-extension-name-value-object.md)의 값 객체 구조를
변경하지 않고, 그 값 객체가 보장해야 하는 허용 문자 정책을 구체화한다.
정규화 순서와 예외 변환의 책임은 ADR 0004의 결정을 그대로 따른다.
