# 고정 확장자 변경 실패 후 전체 정책을 재조회

고정 확장자 체크박스는 기존 `PATCH /api/v1/extension-policies/fixed/{extension}` API를 호출한다. 요청 중에는 모든 고정 확장자 체크박스를 비활성화하고, 성공 응답의 `blocked` 값을 화면의 최종 상태로 사용한다.

PATCH가 실패하면 공통 오류 응답의 `message`를 보존한 채 `GET /api/v1/extension-policies`로 전체 정책을 다시 조회한다. 재조회가 성공하면 fixed와 custom 목록을 모두 서버 상태로 재렌더링한 뒤 PATCH 오류 메시지를 표시한다. 재조회도 실패하면 사용자가 클릭하기 전 상태를 복원하고 최신 상태를 확인할 수 없으므로 페이지를 새로고침하라는 메시지를 표시한다.

## 결정 결과

- 이번 범위는 고정 확장자 PATCH 화면 연동과 새로고침 유지까지다.
- 파일 업로드 허용·거부와 파일 저장은 후속 단계에서 구현한다.
- 확장자는 URL 경로에 넣기 전에 인코딩한다.
- 변경 요청 중에는 다른 고정 확장자 변경도 허용하지 않는다.
- 성공 시 서버 응답을 화면 상태의 단일 기준으로 사용한다.
- 실패 뒤 전체 정책 재조회가 성공해도 PATCH 오류 메시지는 사용자에게 남긴다.
- 새로운 JavaScript 단위 테스트 또는 브라우저 E2E 도구는 추가하지 않는다.
- 기존 API 계약과 Java 백엔드 구현은 변경하지 않는다.

## 결과와 주의점

- 응답 유실처럼 PATCH 적용 여부가 불확실한 실패에서도 화면을 DB 상태에 다시 맞출 수 있다.
- 실패 복구 GET까지 실패하면 화면 상태를 확정할 수 없으므로 클릭 전 상태는 임시 표시일 뿐이며 새로고침 안내가 필요하다.
- JavaScript 상호작용은 기존 API 자동화 테스트와 실제 브라우저 smoke 결과를 함께 근거로 남긴다.
