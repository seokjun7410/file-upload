# 업로드 파일명의 모든 확장자 구간을 차단 정책으로 검사한다

## 문맥

기존 업로드 정책은 파일명의 최종 확장자만 검사했다. 따라서 `test.exe.pdf`는
`pdf`로만 판단되어 `exe`가 차단 정책에 등록되어 있어도 확장자 정책을 우회할 수
있었다.

현재 서비스는 서버 생성 파일명, 저장 위치 격리, 실행 MIME 차단을 함께 적용하므로
이중 확장자만으로 즉시 실행되는 구조는 아니다. 그러나 denylist 정책의 의미가
파일명 구성에 따라 우회되고, MIME 감지로는 텍스트 형태의 스크립트까지 완전히
판별할 수 없으므로 확장자 구간 전체를 검사한다.

## 결정

- 업로드 원본 파일명의 basename에서 첫 번째 점 이후 각 구간을 확장자로 추출한다.
- 확장자 구간은 파일명에 나타난 순서대로 검사한다.
- 각 구간은 기존 `ExtensionName` 규칙으로 trim·소문자화한 뒤 정책과 정확히 비교한다.
- fixed·custom 정책 중 차단 상태인 확장자 구간이 하나라도 있으면 업로드를 거부한다.
- 여러 차단 구간이 있으면 왼쪽에서 처음 발견한 확장자만 `BLOCKED_EXTENSION`의
  `context.extension`에 반환한다.
- 저장 파일명에는 계속 최종 확장자만 사용한다.
- `exefoo`는 `exe`와 일치하지 않으며, `report.final.v2.pdf`는 차단 정책에 등록된
  구간이 없을 때 허용한다.

```text
차단 정책: exe, jsp

test.exe          → 차단
test.EXE.pdf      → 차단
test.pdf.exe      → 차단
test.jsp.png      → 차단
test.exefoo.pdf   → 허용
report.final.v2.pdf → 허용
```

## 결과와 한계

- 중간 확장자를 이용한 denylist 우회를 줄인다.
- 정상적인 복합 파일명은 차단 확장자 구간이 없으면 허용한다.
- 이 정책은 파일 확장자 검사이며 악성코드 검사를 대체하지 않는다.
- MIME 감지, 저장 위치 격리, 서버 생성 파일명 정책은 계속 유지한다.
- 다운로드·미리보기 기능에서 파일을 실행하지 않도록 하는 별도 통제가 필요하다.

## 기존 결정과의 관계

이 ADR은 최종 확장자만 검사하도록 결정한 [ADR 0007](0007-use-final-file-extension-for-upload-blocking.md)을 대체한다.
확장자 정규화와 값 객체 생성은 [ADR 0004](0004-use-extension-name-value-object.md)를 따른다.
