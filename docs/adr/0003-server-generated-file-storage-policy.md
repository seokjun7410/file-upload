# 서버 생성 파일명과 로컬 업로드 저장 정책

## 배경

파일 업로드에서 원본 파일명을 그대로 저장 경로에 사용하면 파일명 충돌과 경로 조작 위험이 생긴다. 또한 파일 입력 오류와 서버 저장 장애를 같은 오류로 처리하면 호출자가 재시도 여부를 판단하기 어렵다.

## 결정

- 허용된 파일은 프로젝트의 `./uploads`에 저장한다.
- 물리 파일명은 서버가 생성한 UUID와 정규화된 마지막 확장자로 구성한다.
- 응답의 `filename`은 실제 생성된 서버 저장 파일명이다.
- 누락·빈 파일·확장자를 추출할 수 없는 파일은 `400 INVALID_FILE`로 거부한다.
- 정책으로 차단된 확장자는 `422 BLOCKED_EXTENSION`으로 거부하며 파일 저장을 수행하지 않는다.
- 저장 장애는 `500 FILE_UPLOAD_FAILED`로 반환하고 내부 경로·예외 세부사항은 외부에 노출하지 않는다.

## 결과

- 원본 파일명이 저장 위치와 분리되어 충돌 및 경로 조작 위험을 줄인다.
- API 호출자는 입력 오류, 정책 차단, 서버 저장 장애를 상태 코드와 오류 코드로 구분할 수 있다.
- 서버 생성 파일명을 사용하므로 원본 파일명 기반 다운로드·표시 기능은 별도 메타데이터 정책이 필요하다.
